# Draft-OPD: On-Policy Distillation for Speculative Draft Models 中文总结

## 一句话概括

这篇论文提出 Draft-OPD，用“目标模型辅助生成 + 在 speculative verification 暴露的错误位置回放”的方式，对草稿模型进行 on-policy 蒸馏，使 draft model 更擅长预测自己在真实 speculative decoding 中会遇到的状态，从而提高 accepted length 和端到端推理加速比。

## 研究背景

Speculative decoding 用一个轻量 draft model 先提出一段 token，再让更大的 target model 并行验证。只要验证机制是 lossless 的，最终输出分布仍然等价于 target model，但速度取决于 draft model 提出的 token 有多少能被接受。

现有主流方法如 EAGLE-3、DFlash 通常用 supervised fine-tuning 训练 draft model：让 draft model 学习 target model 生成的轨迹。论文指出，这种离线 SFT 很快会进入平台期。原因不是训练算力不够，而是训练状态和推理状态不一致：SFT 时前缀来自 target model；真实 speculative decoding 中，验证的是 draft model 自己提出的 token block，accepted length 取决于 draft-induced states。

这自然引出 on-policy distillation：让 target model 监督当前 draft policy 自己诱导出来的状态。但直接套用 OPD 又不可行，因为 EAGLE/DFlash 风格的 draft module 不是独立自回归生成器，强行自己 rollout 容易重复或退化；如果用 target-assisted rollout，则错误 token 被 target model 修正或丢弃，on-policy 信号又消失了。

## 核心方法：Draft-OPD

Draft-OPD 的设计目标是在保持 rollout 稳定的同时，保留 draft model 在真实推理中犯错的位置。方法由三部分组成。

### 1. 带错误位置记录的 target-assisted rollout

训练时仍然使用 speculative decoding 生成高质量 continuation。每轮 draft model 提出长度为 K 的 token block，target model 验证并接受其中前若干 token。Draft-OPD 会记录每个 block 开始的位置作为 anchor。这样最终样本仍然是 target-quality rollout，但 anchor 标记了 draft model 实际出手的位置。

### 2. 从 anchor 回放 draft proposal

收集完 rollout 和 anchor 后，Draft-OPD 从每个 anchor 重新让 draft model 生成 block，并在同一个 draft-generated prefix 上计算两类概率：

- draft model 对自己 token 的 log-probability；
- target model 对这些 draft token 的 log-probability。

关键点是：回放不是只训练最终被 target model 接受的文本，而是让 target model 对 draft model 曾经提出、包括被拒绝的 token 也打分。这就把最有价值的 verification-time 错误重新纳入训练。

### 3. acceptance-aware distillation objective

论文把 draft token 分成 accepted 和 rejected 两类，并使用不同的 KL 方向：

- accepted token：使用 forward KL，让 draft distribution 覆盖 target distribution，强化已经可靠的匹配；
- rejected token：使用 reverse KL，重点惩罚 draft model 自己高概率但 target model 不支持的模式；
- rejected block 内越靠后的 token 权重越低，因为一旦早期 token 被拒，后续 suffix 已经被前面的错误污染，信息价值更低。

最终目标函数是 accepted loss 与 rejected loss 的加权平均。论文实验中两个权重都设为 1。

## 实验设置

实验基于 Qwen3 系列，包括 Qwen3-4B、Qwen3-8B 和 Qwen3-30B-A3B-Thinking-2507。draft model 以 SFT 训练过的 DFlash draft model 为起点。训练和推理中 block size 设为 16。

评测覆盖三类任务：

- 数学推理：GSM8K、MATH-500、AIME25；
- 代码与软件工程：MBPP、HumanEval、SWE-bench Lite；
- 对话泛化：MT-Bench。

OPD 阶段使用 16K prompt pool，来源包括 GSM8K、MATH、AoPS 和 CodeAlpaca。注意论文只使用 prompt，回答由 target model 在线生成，而不是使用静态参考答案。

主要比较对象是 EAGLE-3 和 DFlash。为了公平，所有方法使用匹配的训练 FLOPs budget。

## 主要结果

在 thinking mode、temperature = 0 下，Draft-OPD 将两模型平均 accepted length 从 DFlash 的 5.35 提高到 5.85，并在七个 benchmark 上取得 4.88 倍平均 speedup；相对 EAGLE-3 提升 23%，相对 DFlash 提升 13%。

在 thinking mode、temperature = 0.6 下，Draft-OPD 仍然是平均最快的方法，平均 speedup 为 4.17 倍。论文指出，虽然某些设置下 EAGLE-3 的 accepted length 可能更高，但 EAGLE-3 的 sequential drafting 会限制真实 wall-clock speed，因此 DFlash 风格并行 draft 更适合获得实际加速。

在 non-thinking mode 下，Draft-OPD 也保持优势，平均 accepted length 达到 6.33，平均 speedup 达到 5.17 倍。这说明方法不只是对长推理链有效，也能改善较短生成场景中的 draft-target alignment。

论文还在 SGLang + FA3 backend 上评估 serving throughput。Draft-OPD 在所有模型、任务和并发设置下都超过 DFlash，平均 accepted length 提高 11.2%，在 Qwen3-30B-A3B-Thinking 上最高带来 17% throughput gain。并且在高并发下收益没有消失，说明 accepted length 的提升能转化为实际服务吞吐。

## 消融实验结论

论文做了几组关键消融：

- 只增加 OPD prompt pool 的 SFT 数据不够。EAGLE-3/DFlash 继续在 OPD prompt 生成数据上做 SFT，仍然不如 Draft-OPD，说明收益来自 on-policy distillation，而不是更多 prompt。
- KL 方向很重要。全 forward KL 和全 reverse KL 都弱于 acceptance-aware mixed KL，其中全 reverse KL 最差。
- anchor 位置很重要。随机 anchor 弱于错误位置 replay，说明集中训练 verification-time failure states 更有效。
- rejected-token position decay 有用。去掉位置衰减会降低 speedup 和 accepted length。
- naive target-assisted rollout 不够。只用 target-assisted rollout 会退化成在 target-distributed trajectory 上做 KL-loss SFT，平均 speedup 从 Draft-OPD 的 4.63 倍下降到 4.29 倍，相对下降 7.3%。

## 主要贡献

1. 明确指出离线 SFT 训练 draft model 的平台期来自 offline-to-inference mismatch。
2. 分析了标准 OPD 不能直接用于 draft model 的原因：draft-only rollout 不稳定，target-assisted rollout 又会抹掉 on-policy 错误。
3. 提出 Draft-OPD：通过 anchor/error-position replay 保留 verification-time draft errors。
4. 提出 accepted/rejected token 使用不同 KL 方向的 acceptance-aware objective。
5. 在 Qwen3、DFlash-style draft、SGLang serving 等设置下展示了实际推理加速收益。

## 局限与注意点

- thinking-mode 训练时最大 response length 为 4096 token，而评估使用 8192 token；长输出后段状态覆盖不足，可能还有提升空间。
- 主实验集中在 Qwen3 模型族和 DFlash-style parallel draft architecture；迁移到其他模型、draft 架构和 inference backend 还需要更多验证。
- Draft-OPD 改善的是 lossless speculative decoding 的效率，不改变 target model 输出质量。若使用 lossy verification 或近似解码，方法是否适用仍是开放问题。
- thinking mode 本身更难 draft，因为长推理过程中 target distribution 不确定性更高，draft model 更难精确匹配下一个 token。

## 个人阅读建议

如果关注 LLM 推理系统，这篇论文的价值在于它把 draft model 训练从“模仿 target 的静态轨迹”推进到“训练真实 speculative decoding 中会犯错的状态”。这比单纯堆 SFT 数据更贴近 serving-time bottleneck。

最值得细读的部分是 Section 4.2 的 anchor replay 机制和 acceptance-aware KL objective。它们解释了为什么 rejected token 不是噪声，而是提高 accepted length 的关键训练信号。
